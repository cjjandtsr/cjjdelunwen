## 0. 结论先行

[PROVEN] 目前不能诚实声称“全部问题都已经准确找到并完成因果定案”。已经证明的是：训练后策略不是主要因为碰撞增加而变差，而是整体位移、朝目标净推进和成功状态占用下降，导致 timeout 上升；任务/transition 分布和 terminal advantage/gradient 结构会强化这种退化。

[PROVEN] 本轮新增发现一个独立的 P1 算法执行偏差：当前 rebuild buffer 每个 environment transition、每个 epoch 只随机抽取一个去噪步；冻结 DPPO 官方代码则在 `environment transition x 全部 fine-tune denoising transition` 联合空间 shuffle。当前 $K=10$、$E=5$ 时，本地每个 transition 只有 5 次带放回抽样，预期只覆盖

$$
K\left[1-\left(1-\frac1K\right)^E\right]
=10(1-0.9^5)\approx4.095
$$

个不同去噪步，即约 41%；官方循环每个 epoch 覆盖全部 10 步，5 epoch 共 50 个 transition-step 样本。本地为 5 个，优化样本数相差 10 倍。随机抽一阶估计在严格均匀、独立、充分样本条件下可以无偏，但方差和 update/data ratio 已改变，不能继续称为“官方训练循环等价”。

[JUDGMENT] 最可靠的推进路线不是立即换算法或继续长训练，而是先恢复官方联合索引语义、修复实验身份与观测门禁、把任务目标分布写成显式契约，再用 32 个历史 checkpoint 做 D1b 找到退化首次出现的 update。随后才决定是否需要 role/opportunity weighting、BC anchor 或梯度冲突处理。

## 1. “确保发现所有问题”的可验收定义

[JUDGMENT] 软件与随机训练系统不存在可证明的“绝对无遗漏”。本项目将其改写为可验收条件：所有影响最终目标的生产边界都必须有输入、输出、身份、极端输入、并发、失败恢复和恶意滥用证据；不存在未覆盖的 P0/P1 项。

审计面不是八层，而是十二层：

1. 目标与验收契约；
2. 环境与任务分布；
3. 观测与传感器有效性；
4. 策略表示与容量；
5. 动作协议与动力学执行；
6. reward、终止与截断；
7. critic、return 与 advantage；
8. DPPO likelihood、去噪 credit 与 optimizer；
9. 训练编排、预算和 checkpoint 选择；
10. 恢复、随机性与跨进程确定性；
11. 评估、统计与 Gazebo/PX4 部署；
12. 证据治理、安全、资源与并发。

只有十二层的 P0/P1 coverage matrix 均为 `PROVEN_PASS` 或有经实验隔离的 `OPEN_NOT_CAUSAL_YET`，才允许进入正式多 seed 训练。

## 3. 新发现：为什么“随机一个去噪步”不是官方等价

DPPO 将外层 environment transition 与内层 denoising transition 同时视为训练样本。冻结 vendor 的训练循环先令

$$
N_{\mathrm{train}}=B_{\mathrm{env}}K,
$$

再对 $[0,N_{\mathrm{train}})$ 做 `randperm`，通过 `unravel_index` 还原 $(b,k)$。这保证一个 epoch 对每个 pair 恰好访问一次。

当前 rebuild 先对 $B_{\mathrm{env}}$ 做 permutation，再给每个 $b$ 独立抽一个 $k$。因此：

- 单 epoch 样本从 $BK$ 降到 $B$；
- 某些 $k$ 重复、另一些完全缺失；
- `gamma_denoising=0.8` 与 step-dependent clip 使不同 $k$ 的权重和信赖域不同，缺失不是简单重复样本；
- 配置中的 minibatch、epochs、KL 与 update/data ratio 不再与官方设置同义；
- 当前测试反而断言 1024 transitions 只产生 8 个 batch，固化了错误契约；官方 $K=10$ 时应是 80 个 batch/epoch（若 minibatch 仍为 128）。

[JUDGMENT] 这项必须修复，但不能孤立地把 optimizer steps 放大 10 倍后直接长训。应先在 frozen bank 上验证全 $K$ loss/gradient、内存和 KL，再按“联合 pair 数”重新标定 epochs 或 minibatch，防止更新强度突然扩大。

## 4. 理论与一手经验如何支持修复路线

1. [FACT] Policy Gradient Theorem 表明策略更新估计的是访问分布下 advantage 加权的 log-policy 梯度；因此改变 task/role 初始分布就改变优化目标，而不只是“数据更丰富”。若目标是 role-uniform 而采样不是，必须显式重采样或做分布权重校正。来源：Sutton et al., NIPS 1999。
2. [FACT] PPO 只约束同一采样分布附近的代理目标，不保证跨任务能力不退化。来源：Schulman et al., arXiv:1707.06347。
3. [FACT] DPPO 官方实现把 batch 定义在 environment steps 与 denoising steps 的联合空间，并在训练循环展开全部 pair。来源：Ren et al., arXiv:2409.00588；官方 GitHub/vendor。
4. [FACT] Gymnasium 与 Time Limits in RL 都要求区分 termination 与 truncation；当前 GAE 的这部分实现正确，因此不应凭 timeout 增加就误改 bootstrap。
5. [FACT] PPO 的代码级细节能显著改变行为；“loss 公式相同”不足以证明算法等价。来源：Engstrom et al., arXiv:2005.12729；Andrychowicz et al., arXiv:2006.05990。
6. [FACT] 官方 DPPO core 提供可选 BC regularization；RialTo 的 imitation-augmented PPO 也用示范项约束物理可行行为。因此 BC anchor 有理论与机器人经验依据，但它是条件性二线修复，必须证明没有抹掉 recovery/OOD 学习信号。
7. [FACT] PCGrad 在测得多任务梯度冲突时可投影冲突分量，并有多任务 RL 实验支持；但作者官方仓库公开的是 TensorFlow 实现。因此本项目只把它列为“简单分层采样仍失败且 D1b 测得稳定负 cosine”后的备选，不直接采用。
8. [FACT] PyTorch 官方明确说明“设置一个 seed”不等于跨版本/平台完全复现，并要求控制 Python、NumPy generator、worker 与确定性算子。更关键的是，本项目 task_seed 应由稳定任务身份派生，不能依赖 Python set 枚举顺序。

## 5. 三种修复路线

### 路线 A：最小补丁后立刻训练

内容：修复 set 顺序、box 几何、接上 no-ray gate、恢复全 $B\times K$，随后单 seed 重训。

优点：最快。缺点：没有定位退化首发 update，也没有确认 role balance、BC anchor 和 critic tail 的相互作用；一次长训失败后仍无法归因。

### 路线 B：证据门控、保留官方核心（推荐）

顺序：

1. P0 完整性修复：稳定 task identity、真实依赖图 hash、统一几何 oracle、reset 最终复检、观测 validity gate、endpoint 连续误差与四 role 统计；
2. DPPO parity 修复：恢复全 `(transition,k)` 联合索引；保持官方 loss 聚合；新增 pair coverage 和 optimizer-step 契约；
3. D1b：32 个 checkpoint 跨点只读复评分，找出首次 movement/goal approach、terminal sign、role gradient 与 denoising-step drift；
4. frozen-bank 反事实，不更新参数：task-uniform vs role/opportunity-balanced、global vs role-conditioned normalization、BC anchor on/off、共享 vs 独立 weight decay；
5. 3 个 seed 的短 pilot，只允许 NaN/Inf、身份/观测失效、无 actor update 等硬故障提前停；
6. 达标后正式预算、lightweight paired endpoint、多 seed CI；最后进入 Gazebo/PX4。

优点：每一步都能决定下一步，最小化再次长训却无法解释的风险。缺点：比路线 A 多一个 D1b 和短 pilot 周期。

### 路线 C：立即引入 PCGrad/CPO/新 RL 算法

优点：理论工具更强。缺点：会同时改变算法、采样、目标和训练预算，破坏当前已建立的 DPPO attribution；PCGrad 还没有作者官方 PyTorch 实现可直接复用。当前证据不足，不推荐。

## 6. 推荐方案的具体门禁

### 6.1 不启动训练前

- production dependency manifest 无漏文件；相同输入跨 5 个新进程 task sequence/task_seed hash 完全相同；
- 每个 role 的 task、episode-start、transition、terminal opportunity 四种占比同时记录；
- 1024 transitions、10 denoising steps：每 epoch 10240 个唯一 pair，所有 $k$ 各 1024 个；若 batch=128，则每 epoch 80 个 batch；
- no-ray metadata 缺失或超过标定阈值时 fail closed，不入 buffer；
- start/goal 在扰动后满足同一 primitive 几何 clearance；A* classification 不再决定物理有效性；
- endpoint record 包含 goal xyz、final 3D/xy/z error、末速、四 role；
- D1b 能输出每 checkpoint 的 outcome x role x denoising-step 梯度和符号错误。

### 6.2 训练与评估

- 不以 reward 平滑或单 seed SR 上升作为通过；
- safe-arrival 与 continuous final error 是主指标，碰撞、timeout、提前避障、support envelope、dense recovery 为分层能力指标；
- 每个 seed 使用冻结 paired bank；报告 world-cluster 与 seed 级不确定性；
- lightweight 仅用于 admission；最终部署结论必须由 Gazebo/PX4 闭环给出。

## 7. 当前明确判断

[JUDGMENT] 现阶段已经足以否定“只是 Reward v1.7 写错”或“mean logprob 写错”的局部解释，也足以确定下一步不应继续原配置长训。

[JUDGMENT] 还不能把单一根因锁死在 role imbalance、critic 或新发现的去噪 undersampling 任一项上。它们处于同一反馈链，需要 D1b 首发时点与 frozen-bank 反事实切开因果。

[JUDGMENT] 推荐路线 B。它最大程度保留官方 DPPO 与现有 attribution，同时直接修复已证实的完整性缺陷，并把尚未定因的机制变成最少次数、可证伪的实验。

## 8. 已冻结的准确到达契约

[PROVEN] 用户在 2026-09-10 明确：给定目标点后，策略根据无人机状态和点云实时规划、避开障碍并到达目标；进入目标点 0.5 m 内即可视为到达。

[JUDGMENT] 实现与评估统一采用三维欧氏距离球：

$$
\texttt{reached}=\left(\lVert p_t-g\rVert_2\le0.5\ \mathrm{m}\right)
\land \neg\texttt{unsafe\_terminal}.
$$

不增加最终 yaw、末速或驻留时间硬门槛。现有额外 `|z-z_g|<0.3m` 条件与用户目标不一致，应在版本化设计和测试通过后移除。为避免 0.5 m 二值阈值掩盖精度差异，评估仍记录 final 3D/xy/z error 的 median、P90、P95 和 paired delta。
