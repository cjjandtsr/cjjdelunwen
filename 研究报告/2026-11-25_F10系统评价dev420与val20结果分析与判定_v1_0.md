## 三、逐条件归因【事实】
评价是确定性的。P6 与 P6 + g1 在同一条件下，从第一次引导改变输出的那个决策起才开始分岔。
- 33 个结局改变的条件（28 个新增、5 个流失），分岔点**全部**落在一个触发了引导的决策上。
- 387 个结局不变的条件中，216 个全程逐位相同，171 个中途分岔但结局相同。

所以结局变化可以完全归因于引导，不是仿真噪声。5 个流失集中在两个任务：
- `bottleneck_corridor__000016__cfg02`：3 个，第 8 个决策处分岔，修正量约 0.39 m；
- `s_turn_multi_obstacle__000044__cfg01`：2 个，第 15 个决策处分岔。

## 四、读法
1. 【事实】P6 + g1 是本项目第一个在 dev420 上碰撞与到达同时改善、并达到预先登记采纳标准的手段。可通行任务上的碰撞降为 0（7 → 0），被挡任务到达 34 → 50。
2. 【事实】g1 比 G0 推得更强：新增 28 对 19，但也带来 5 个流失（G0 为 0）。两者的到达差 304 对 300，在这一规模下不能区分优劣。
3. 【事实】强化学习后训练是系统的主要贡献者：同样加引导，P6 比 BC 多 134 个到达。BC 的主要失败是超时（123），引导解决不了超时；在 BC 上，引导把 21 个碰撞变成了超时。
4. 【推断】引导与强化学习后训练互补：后训练解决"走得到"（BC 的超时 123 → P6 的 1），引导解决"近处推开"（碰撞 −24）。
5. 【局限】
   - dev420 是开发集，g1 是在同一批训练世界的库任务上选出来的，所以 Q1 是开发结论；
   - val20 只有 80 个条件，差别在 ±4 以内，只能说方向一致；
   - 被挡任务仍是主要失败：P6 + g1 在被挡任务上碰撞 114/165，任务层面 ≥ 3/5 只从 7 个增加到 8 个。

## 七、附：归因计算的代码
```python
# 输入同 f10_recount.py；A、B 分别为 P6 #E2 与 P6 #E4 的 {(task_id, repeat): 原迹行列表}
def first_div(La, Lb):
    Ta = [t for t in La if t.get('type') == 'transition']; Tb = [t for t in Lb if t.get('type') == 'transition']
    for i, (a, b) in enumerate(zip(Ta, Tb)):
        if a['executed_action_4x11'] != b['executed_action_4x11']:
            pm = b['probe_metrics']
            return i, bool(pm['guided']) or bool(pm['triggered_denoise_steps']), pm['delta_exec']
    return None, None, None
# 对每个条件：结局不同 → 记录分岔点是否在触发引导的决策上；结局相同 → 记录是否全程逐位相同
```
