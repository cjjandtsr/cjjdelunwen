## 0. 先给结论

[JUDGMENT] 期刊论文的主对比组建议调整为：

1. **EGO-Planner**：传统局部规划器参考，同时如实披露它是示范航迹来源。
2. **DDPM-BC**：已完成 UAV 任务适配、但未经 DPPO 后训练的扩散策略，是判定 DPPO 净改善的直接基线。
3. **FM-BC**：未经 DPPO 后训练的 Flow Matching 策略，用于表明快速生成式策略在相同 UAV 任务中的性能与延迟边界；它是对照，不重新定义为论文第二条主方法线。
4. **Gaussian Chunk-PPO**：在本项目统一观测、动作、reward、环境和交互预算下训练的常规连续动作 PPO，作为生成式策略之外的主 RL 基线。
5. **DDPM-BC+DPPO**：本文完整方法。

[FACT] 公开 GitHub 上能找到可下载并在原生环境中运行的 UAV PPO/APPO checkpoint，例如 [NavRL](https://github.com/Zhefan-Xu/NavRL)、[AirGym](https://github.com/emNavi/AirGym)、[ntnu-arl/rl_nav](https://github.com/ntnu-arl/rl_nav) 和 [active-perception-RL-navigation](https://github.com/ntnu-arl/active-perception-RL-navigation)。

[JUDGMENT] 但截至本次检索，**没有找到能不经重训练、直接接入本项目“自我中心三维点云+飞行状态/目标 → 11 维多步航迹块”合同的常规 RL 预训练策略**。这是对本次系统检索结果的边界判断，不是对全球所有未公开或未被索引项目的不可能性证明。

## 1. “可以直接下载使用”必须分三层

| 层级 | 判定标准 | 本次结果 |
|---|---|---|
| L1 算法代码可用 | 有成熟 PPO/SAC/TD3 实现，可接 Gymnasium 环境 | 有；SB3、CleanRL、Sample Factory 都满足 |
| L2 原生系统可运行 | 有 UAV 环境、checkpoint 和原仓库推理入口 | 有；NavRL、AirGym、`rl_nav`、active-perception 满足 |
| L3 本项目可插拔 | 观测语义、维度、动作语义、控制频率、动力学与本项目一致，不改策略即可比较 | 未找到 |

[JUDGMENT] 只达到 L2 的 checkpoint 可以证明“常规 RL 能做 UAV 避障”，但不能直接回答“在本文相同任务定义下，DPPO 扩散策略是否优于常规 RL”。

## 3. 为什么预训练 UAV PPO 不能经 adapter 后就当作公平基线

[PROVEN] 策略学到的是条件分布 $\pi(a\mid o)$。若外部策略使用的观测 $o'$ 和动作 $a'$ 与本项目 $o,a$ 不同，仅构造确定映射 $o'=f(o)$、$a=g(a')$ 并不保证保留原策略的最优性、安全性或闭环稳定性。特别是速度/加速度指令到多步航迹块不是可逆的简单坐标变换，而是改变了决策时域和控制器职责。

[JUDGMENT] 因此，外部 checkpoint 只有两种合理用法：

- 在它的原生完整系统中运行，作为 **system-level external reference**，并披露感知、控制、安全模块和环境差异；
- 使用其代码结构/训练框架，在本项目统一协议下重新训练。

## 4. 正式常规 RL 基线建议

### 4.1 主基线：Gaussian Chunk-PPO

[JUDGMENT] 建议用 SB3 作为成熟 PPO 实现基底，但在本项目中训练新的 Gaussian actor-critic。为了回答“扩散策略+DPPO 相对于常规 RL 的优势是否来自策略分布形式”，主基线必须尽量匹配：

| 要素 | 统一要求 |
|---|---|
| 观测 | 同样的自我中心点云、状态与目标信息；不向 PPO 额外提供全局障碍物真值 |
| 动作 | 同样的 11 维 step-wise UAV 动作语义与多步航迹块；预测/执行长度按最终正式协议固定 |
| 环境 | 同一训练 world 分布、同一 eval-only world、起终点和 seed |
| 学习信号 | 同 reward、终止语义、安全到达定义与物理约束 |
| 交互预算 | 同样的 environment transitions；同时报告 wall-clock，但不用不同吞吐的平台冒充样本效率 |
| 评估 | 同一闭环控制器、传感器来源、碰撞体、成功半径和最大时长 |

[JUDGMENT] Gaussian actor 可对展平后的航迹块建模对角高斯分布，再 reshape 回多步 $11$ 维动作。这是“常规随机策略对多步航迹块的适配”，不引入 diffusion denoising、轨迹 projection 或后处理救场。

### 4.2 初始化的公平性：建议两个层次，不混为一个结论

| 对照 | 回答的问题 | 地位 |
|---|---|---|
| **PPO-from-scratch** | 在没有示范预训练时，常规 RL 能否从头获得有效 UAV 避障策略 | 训练效率/预训练价值对照 |
| **Gaussian-BC+PPO** | 在两者都利用同一 EGO 示范数据后，常规 Gaussian policy + PPO 与 diffusion policy + DPPO 谁更好 | **更清洁的策略形式因果基线** |

[JUDGMENT] 如果只比较“有 988 episodes 示范预训练的 DDPM+DPPO”和“纯随机初始化 PPO”，结果会同时混入示范数据、表征预训练和策略分布三种差异。这组对比可用来强调预训练的工程价值，但不能单独证明 diffusion/DPPO 结构更优。

### 4.3 为什么不首选 SAC/TD3 作为主基线

[FACT] SAC 和 TD3 都有成熟开源实现，且在 UAV 导航文献中常见。

[JUDGMENT] 但本文完整方法是 DPPO，主对照选 PPO 可保持 on-policy 数据制度、GAE、clip 目标和交互预算更接近。同时，航迹块是高维连续动作，离策略 critic $Q(s,a)$ 的建模难度不应成为主实验中的额外混杂因素。项目历史 Route B DSRL-SAC 也只能证明噪声空间高维 critic 有风险，不能当作直接 Gaussian PPO 已失败的证据。

## 6. FM 对照的表述与公平性边界

[FACT] 本项目的 FM 模型已通过模仿学习训练；“未经 DPPO 训练”不等于“未训练模型”。论文应使用 **FM-BC** 或“未经强化学习后训练的 FM 策略”，不用“未训练 FM”。

[JUDGMENT] 只有在 DDPM-BC 和 FM-BC 使用相同数据、相同观测/动作定义、相当编码器与训练预算时，才能把差异主要解释为 DDPM 与 Flow Matching 生成机制差异。若现有 FM 同时使用 AnchorHead、CFG、SFP 或不同 checkpoint 选择标准，它仍可参与对比，但应标注为“完整 FM 系统对照”，不能宣称为纯 solver 消融。

## 7. EGO-Planner 的特殊对比边界

[FACT] [EGO-Planner](https://github.com/ZJU-FAST-Lab/ego-planner) 的原始方法是不显式构建 ESDF 的梯度局部规划器（RA-L 2021，DOI: [10.1109/LRA.2020.3047728](https://doi.org/10.1109/LRA.2020.3047728)），可从深度/点云与里程计建立局部障碍信息。它不应被简化成“已知全局地图规划器”。

[JUDGMENT] 公平性应来自相同外界可用信息和任务条件，而不是强迫 EGO-Planner 放弃其原生局部地图。两者使用相同传感器数据源/量程、同一动力学和控制器、同一起终点和世界；不向任一方输入全局障碍物 JSON。论文同时披露 EGO-Planner 是数据教师，并将“超过 EGO”限定为指定测试协议和指标下的结果。

## 8. 评价指标与不允许的结论跳跃

[JUDGMENT] 主表仍应以“安全到达”为首要终点，再拆分项目真实能力缺口：

- 总体 safe success rate 及 collision/ground-contact/timeout/invalid 互斥失败率；
- 提前避障 onset 和最小障碍距离；
- 密集障碍通行与局部陷阱恢复；
- $x/y/z$ 低支持度空间中的有效航迹输出、安全到达和飞行包络；
- 推理延迟、规划频率与执行可行性，作为部署指标而非唯一创新点。

[JUDGMENT] 以下结论在正式数据出现前都不得预写：DPPO 必然突破 BC 上限；完整方法必然优于 EGO-Planner/FM/PPO；外部 pretrained policy 在本项目世界中具有同等性能；或 lightweight rollout 等价于 PX4/Gazebo 闭环。

## 9. MC 合规性与风险

| 项目约束/风险 | 本报告处理 |
|---|---|
| MC-1 / MC-5 | Gaussian PPO 自身输出执行航迹块；不用 post-hoc repulsion/projection 修改轨迹 |
| MC-2 / MC-3 | DDPM+DPPO 仍是完整方法；安全通过学习信号和硬物理失败定义处理 |
| MC-4 | Gaussian-BC 仅使用已冻结 EGO 数据，不重采集示范 |
| 外部 safety shield 混淆归因 | NavRL 等只作系统参考；若实验必须单独标识 policy-only 与 full-system 设置 |
| 高维 Gaussian chunk 难训 | 这是常规策略在相同任务合同下的真实能力问题；可调整网络容量和数值实现，但不得为它降维成另一个任务后再宣称同协议公平比较 |
| FM 配置差异 | 可作完整系统对照；只有 matched recipe 才能解释为 DDPM-vs-FM 因果 |

## 10. 最终判断

[JUDGMENT] **有可直接下载运行的常规 UAV RL 策略，但没有可直接插入本项目并构成公平主基线的策略。**

[JUDGMENT] 最稳妥的期刊路线是：把 DDPM-BC 和 FM-BC 明确加入主对比；用 SB3 或经过对照审计的 CleanRL 实现在统一协议下训练 Gaussian Chunk-PPO；如果资源允许，再增加 Gaussian-BC+PPO 以消除示范预训练优势的混杂；NavRL 只作可选外部系统参考。
