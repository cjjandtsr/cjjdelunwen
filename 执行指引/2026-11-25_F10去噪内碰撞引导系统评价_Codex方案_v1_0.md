## 一、目的
把"扩散策略 + 去噪内碰撞引导"作为一个部署系统，严格评价，回答三个问题：
1. **系统是否比策略本身更安全地到达？**比较 P6 + 引导与 P6，主看碰撞与到达。
2. **强化学习后训练在系统中是否必要？**比较 P6 + 引导与 BC + 引导。
3. **系统与经典规划器相比处在什么位置，在未见世界上是否成立？**与 EGO 对比，并在 val20、test12 上评价。

论文中策略结果与系统结果分开报告，不混用（与项目约束中"系统到达率与策略到达率分开报告"的规则相同）。

## 二、系统定义（预先固定，评价期间不改）
- **引导：**`scripts/routea_denoising_guidance.py`，与 F9 教师和影子测量所用的实现相同。
  - 只在 DDIM 最后 3 步作用；x̂₀ 先截断，ε 在截断前计算并保留；每次更新为 `clamp(x̂₀ − η·g/‖g‖∞, −2, 2)`。
  - 代价为机载点云（去掉 z < 0.1 的点）上的 Σ[d_safe − d]₊²，加地面项 [0.5 − z]₊²。
- **主设置 g1**（d_safe 0.6、η 0.4、M 4）。
  - 选法：F9 第 0 步在 85 个库任务 × 5 次上比较六组设置，g1 的教师 1 m 到达最高（333），救回 P6 失败条件最多（101）。
  - 说明：这 85 个库任务与 dev420 来自同一批训练世界，所以这是在开发集上选参。dev420 上的系统结果只作开发结论；泛化结论只看 val20 与 test12。
- **敏感性设置 G0**（d_safe 0.6、η 0.2、M 2）：dev420 已有结果（300 / 118 / 2），只补 val20 与 test12。
- **评价协议：**#E2（截断 2.0、确定性采样、LoRA 分支）+ 上述引导，登记为 **#E4（g1）**与 **#E4b（G0）**，由 Codex 写入编号规范。
- 策略编号不变：P6@u256、BC。系统记为"P6@u256 #E4"等。

## 六、必报描述项
- 到达、碰撞、超时，分开报告被挡任务与可通行任务、目标高度 ≤ 3 m 与 > 3 m、障碍密度；
- 配对新增与流失到达；近目标碰撞；险情（< 0.3 m）；
- 引导触发率：被触发决策占比，触发时执行段的平均修正量；
- **每决策计算耗时：**有无引导各取 1000 个决策，给中位数与 p95，在同一 WSL GPU 上测；
- G0 与 g1 的差别，作为敏感性。
