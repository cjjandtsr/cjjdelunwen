# 待回传数据格式说明（供WSL侧导出）

把文件放到`图表/data/`后，运行`python 图表/make_figures_v3.py --check`确认识别，再运行`python 图表/make_figures_v3.py`即可重新出图。没有这些文件时，脚本照常出图，只是相应部分用现有数据的版本（见各节"缺失时"）。

所有文件均为UTF-8 JSON。字段名区分大小写；多出的字段会被忽略。

## 1 EGO-Planner评价结果 `b3_ego_records.json`

**用途：** 图5加第三根柱（深灰斜线），图6加深灰菱形；表4、表5补EGO列。

**格式：** 与`2026-10-15_v3_全策略原轨迹分析数据.json`中`records`的单条记录相同，至少包含下列字段：

```json
{
  "records": [
    {
      "policy": "ego",
      "task_set": "original",
      "task": 30,
      "task_id": "routeA_rl_v1__dense_recovery__rl_train__cul_de_sac_trap__000019__dev20261009__cfg02",
      "world": "routeA_rl_v1__dense_recovery__rl_train__cul_de_sac_trap__000019",
      "repeat": 1,
      "family": "cul_de_sac_trap",
      "blocked": true,
      "outcome": "reached"
    },
    {
      "policy": "ego",
      "task_set": "new",
      "new_task_index": 9,
      "task_id": "89d02995a38f6e4c57526aa1",
      "world": "routeA_rl_v1__dense_recovery__rl_test__cul_de_sac_trap__000021",
      "repeat": 1,
      "family": "cul_de_sac_trap",
      "blocked": true,
      "outcome": "collision"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `task_set` | `original`（bank 84任务）或`new`（P3新任务24项）。缺省时按`world`中是否含`__rl_test__`判断 |
| `task` | 原任务编号0—83，与v3记录一致（图5区间按任务重采样要用） |
| `new_task_index` 或 `task_id` | 新任务：`new_task_index`为`P3_data_tables.md`"新任务全部24项"表的N列（1—24），或`task_id`为该表的24位hash |
| `family`、`blocked` | 与学习策略记录一致 |
| `outcome` | `reached`、`collision`、`time_limit`三者之一（触地、越界等按v3口径归入`collision`） |

行为指标（`max_cross_track_m`、`normalized_best_gain`、`crossed_goal_plane`等）请用v3同一脚本从原迹重算后一并写入，表7和后续分析会用到；画图5、图6只需要上表字段。

**缺失时：** 图5、图6只画BC和后训练。

**每任务1回合还是5回合：** 两种都可以。图5的区间按任务重采样，回合数不同不影响计算；`n`按实际回合数标注。

## 2 中间状态逐状态首段推进 `p3_first_step_by_state.json`

**用途：** 图8(a)由汇总柱图改为24行配对点图。

```json
{
  "source": "P3原始结果路径与sha256",
  "states": [
    {"state": 1, "n_samples": 50,
     "bc_mean_progress_m": 0.21, "rl_mean_progress_m": 0.47,
     "bc_positive": 33, "rl_positive": 44}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `state` | P编号1—24，与`P3_data_tables.md`"共同初态全部24状态"表一致 |
| `n_samples` | 该状态每个策略的开环样本数（合计应为1200） |
| `*_mean_progress_m` | 首个执行前缀的平均目标推进（m） |
| `*_positive` | 首段推进为正的样本数 |

脚本会核对加权均值是否等于0.355/0.593 m、正推进数是否等于851/1000、样本总数是否为1200，不一致时打印警告（仍出图）。

**缺失时：** 图8(a)画两策略的汇总柱图并标正推进比例。

## 3 全部回合执行路径 `v3_executed_paths.json`

**用途：** 类别轨迹占据密度图（§3.9备选）用全部回合，替代目前205个案例回合的预览。

```json
{
  "paths": [
    {"policy": "bc", "task": 30, "repeat": 1,
     "path": [[x, y, z], [x, y, z]]}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `policy` | `bc`或`rl_2f3f9914db78_u32`（其他策略会被忽略） |
| `task`、`repeat` | 与v3记录一致；起点、目标、族别和是否受阻由脚本从`task_meta`读取 |
| `path` | 该回合全部执行段拼接的位置序列（世界系，m），即各周期`executed_path`首尾相接 |

只需原任务84×5×2=840条。文件较大时可以只导出密集受阻任务（U形陷阱、瓶颈通道、S形多障碍中`line_blocked=true`的任务）。

**缺失时：** 用`case_cycles`中的案例回合出预览，文件名带`_preview`。
