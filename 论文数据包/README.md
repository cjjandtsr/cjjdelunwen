# 论文数据包

《面向无人机端到端自主避障的UAV-iDP3扩散策略及其强化学习微调》正文与补充材料所用全部实验数据。

- 日期：2026-11-10。
- 对应稿件：论文仓库 `cjjdelunwen` 分支 `paper-v2-restructure` 中的 `论文大稿_v4.md`、`补充材料.md`，以本文件所在提交为准。

这份数据包有两个用途：审稿人索取原始数据时可以直接提供；其他人或智能体复核论文时，可以从逐回合记录一路重算到正文中的每一个数字。

数据包内的文件都由脚本从上游原始记录生成，汇编脚本为 `07_脚本/build_data_package.py`。汇编时自动做了一次校验：用逐回合文件按正文口径重新计数，所得结果与正文表 4 的成功、碰撞、超时计数一致。所有文件的 SHA256 见 `sha256sums.txt`。

## 三、统计口径与数据去除

### 统计口径

**成功的判定**
- 正文：单次飞行中，在发生碰撞之前进入目标 1.5 m 范围即为成功。
- 训练奖励：到达范围为 0.5 m。
- 两者都在评价完成后确定。评价前登记的标准是按每次评价单独统计、0.5 m 判成功，表 S3 按这一原标准给出了全部 199 个任务的结果。

**运动学按任务统计**
- 每个任务评价 5 次，至少 3 次成功即记该任务成功。
- 否则按失败次数较多的一类记为碰撞或超时，两类次数相同时记为碰撞。

**Gazebo 按任务统计**
- 每个任务飞行 2 次，至少一次成功即记该任务成功。
- 两次都失败时，任一次碰撞记为碰撞，否则记为超时。
- 飞出场景边界（lost）的飞行记为超时，与运动学评价一致。这一点于 11-10 修改；修改前 lost 记为碰撞，仅影响表 S5 的 4 个单元格。

**区间估计**
- 按场景聚类自助法重抽样 20000 次，随机种子 2026102601。
- 这是工程上的判断阈值，不是显著性检验。

**路径效率**
- 定义为起终点直线距离与实际飞行路径长度之比。
- 实际路径长度计至首次进入 1.5 m 范围的位置，再加上该位置到目标的距离。
- 在成功任务的成功飞行上取中位数。

### 数据去除（补充材料 S3、S4 已写明）

**运动学：去除 13 个任务，从 42 个场景、199 个任务减为 40 个场景、186 个任务**
- 9 个为 cul_de_sac_trap 类任务：UAV-iDP3 与本文方法 5 次均失败，在看到结果之后决定去除（用户 11-09）。
- 4 个为 initial_yaw_offset_corridor_000015 场景的全部任务：Codex 核对发现该场景的障碍布局、起飞点和区域字段与训练场景 …000012 完全相同，因此整个场景去除（用户 11-10）。这一去除依据的是测试场景不得与训练场景重合的协议，两种方法在这 4 个任务上的结果相同。

**Gazebo：去除 8 个任务，从 48 个减为 40 个，在全部飞行完成后决定**
- 去除清单见 `03_Gazebo/exclusions.json`。

去除规则（用户 11-09 定）：只针对删除操作，要求删除后每个场景至少保留两个任务；整个场景去除不受此限。

## 四、证据边界

以下事项已核实到所写的程度，超出部分没有证据。

| 事项 | 现有证据 | 边界 |
|---|---|---|
| 预训练中的可微碰撞代价（正文式(3)，λ_geo=0.5） | 注册 BC 的内嵌配置中，训练类为 `DiffusionPointcloudPolicy`，配置里没有 collision_lambda。项目仓库中该类的 `compute_loss` 只有行为克隆的均方误差，训练日志只记 `bc_loss`。可微碰撞代价的实现只出现在 `Phase1aPolicy` 系列中 | **未确证**：没有证据表明评价所用的 UAV-iDP3 在预训练中实际计算了碰撞代价。用户 11-10 决定正文暂不修改 |
| BC 训练设置 | 检查点内嵌配置：AdamW 优化器，学习率 1e-4，余弦调度，批大小 60，301 轮，随机种子 42，验证比例 0.1。检查点记录 epoch 301、global_step 246218，与 818 步/轮 × 301 轮一致 | 原始训练日志只记到第 299 轮 |
| 示范数据 | 共 988 个回合、60151 帧，训练集 889 个、验证集 99 个；训练窗口 49090 个，每轮 818 步，与日志一致 | 训练/验证的划分是按代码和随机种子重建的，不是历史保存的划分文件。服务器上的原始示范目录已不存在，WSL 中的副本是已知唯一副本 |
| ±30° 偏航旋转增强 | 数据集代码中的默认参数 | 注册配置中没有单独列出这一项 |
| Gazebo 中碰撞的判定 | 288 次飞行中有 96 次记为 collision，其中 70 次为坠地、26 次为翻覆，没有一次由障碍判定触发。障碍判定按机体中心是否进入障碍，不计机体半径 | 正文写作“碰撞以机体坠地或翻覆判定，机体与障碍接触而未失稳的情形不计为碰撞”。服务器上现存的 monitor 文件已与运行绑定，但其修改时间比第一批飞行开始时晚约 11 分钟，第一批飞行所用的 monitor 版本无法逐回合证明 |
| Gazebo 机型碰撞几何 | iris_D435i 的 SDF 文件在 11-06 清单与 11-10 服务器原位核对中哈希一致。机身碰撞箱 0.47×0.47×0.11 m，旋翼碰撞圆柱半径 0.128 m | 这是仿真模型的碰撞几何，不是实体机的实测外形。运动学训练中使用的碰撞体半径为 0.1 m |
| 测试场景几何 | 测试与训练、验证场景之间，以及测试场景彼此之间，几何完全相同的情况为 0（去除 000015 之后） | 测试场景 front_offset_obstacle__000050（即图 6 的密集类示例）与验证场景 …000049 布局相同、尺寸相差约 5%，两者不完全相同。验证场景只用于方法开发，不参与训练 |
| 训练用时 | 后 128 轮用时 45376 s（12.6 h），GPU 为 RTX 4060 Laptop，均有原日志 | — |
| 第二次训练运行 | 见表 S2 与图 S1 | 评价前登记的判据 R4、R2 在本次训练预算下不符合采纳标准。补充材料如实给出，正文第 5 章将其列为局限 |

## 六、重新生成

```bash

python3 -I $A/kin_task_level.py <rows.json> $A                      # 运动学按任务统计 → oprime_task/
python3 -I $A/gazebo_analysis.py jindu/gazebo_3method_288_run01 $A/gazebo $A/gazebo/exclusions.json
python3 -I $A/paper_data_workbook.py <rows.json> $A x 论文大稿_v4.md 研究报告/2026-11-08_论文数据表.xlsx
python3 -I $A/build_data_package.py <rows.json> 论文数据包 <Codex几何包目录> <图6数据目录>
python3 $A/build_docx.py 论文大稿_v4.md 导出/论文初稿_v4.docx
```

`rows.json` 已包含在 `01_运动学逐回合/` 中。路径效率的重算需要上游的轨迹文件。
